# 设计笔记

记录这个架子从第一版到定稿的取舍过程，重点写**为什么改**，而不只是最后是什么样。里面有两次推倒重来，还有一次判断失误。

## 背景

热敏打印机摆在桌上，电源线和 USB 线从机身后面出来，盘在桌面上。快递面单要铺在打印机后侧出纸口那一带，偏偏线就盘在那儿——纸一压上去就被线拱起来，铺不平、总是翘着。

需求很朴素：把面单垫高 25mm，给线缆留出一个可以藏进去的空间。

- 台面要能完整放下 8×13cm 的面单
- 增高 2.5cm，正好跳过线缆凸起的高度
- 线缆从任意方向都能塞进去，不用拔插头

## 迭代历程

### v1：完整壳体（88.8 cm³）

第一版按"最稳妥"的思路做：顶板 + 底板 + 四面围合，内部两条纵向隔板，隔板上各开 3 个 φ14 过线孔。

| 部件 | 尺寸 |
|---|---|
| 顶板 / 底板 | 3.2 / 1.6 mm |
| 壁厚 | 3.2 mm |
| 竖直棱 | R6 |
| 隔板 | 2 条全高，φ14 × 3 |

结构上是合理的，隔板顺带把顶板的无支撑跨度从 79.6mm 压到 33mm 以内，正放打印完全免支撑。

但实体体积 88.8 cm³，打出来将近 45g，用料明显过量——底板那 1.6mm 一整片就占了 18 cm³，它唯一的贡献是不让线从底下漏出来，而这个需求本身并不存在。

### v2：拆底板、拆隔板，加弹性卡扣（63.5 cm³）

- 去掉底板：底部全开，-18 cm³
- 去掉两条隔板：-17 cm³
- 顶板 3.2 → 3.6mm，补偿刚度损失（抗弯刚度 +42%）
- 侧壁上做 4 个弹性卡扣，把线缆夹住

卡扣的设计是：两条 1.6mm 薄臂 + 3.4mm 夹口（比线径窄，靠过盈摩擦夹持）+ 1.6mm 封底 + 槽口喇叭（3.4 张开到 6.8，方便按进去）。每侧壁 2 个，沿 Y 方向前后贯穿 8mm。

关键的一点：卡扣从 Z=0 直接长起来，贴着侧壁内侧，所以虽然它悬在腔体里，打印时其实是**从热床一路长上来的竖直墙**，正放打印不需要支撑。如果做成内侧薄壁上的悬臂夹子，就必须加支撑了。

体积降到 63.5 cm³，-28%。

### v3：全部简化掉（61.9 cm³）

用了几天发现卡扣有点过度设计：线缆本来就躺在腔体里不会跑，而且卡扣要求对准才能塞进去，反而比"直接扔进去"麻烦。

删掉全部 4 个卡扣，只剩顶板 + 左右两片侧壁：

```
     ┌──────────────┐   ← 顶板 3.6
     │              │
   ┌─┘              └─┐ ← 侧壁 3.2 × 2
   │                  │
   └──────────────────┘
       前、后、下 三面全通透
```

61.9 cm³，比 v1 少了 30%，PLA 约 31g。结构上是「П 形槽」，刚度靠顶板兜，前/后/下三个方向都能塞线。

## 最终参数

| 项目 | 数值 |
|---|---|
| 台面净空（挡边内侧） | 80 × 130 mm |
| 台面高度 | 25 mm |
| 总高（含挡边） | 29 mm |
| 外廓 | 86 × 133 × 29 mm |
| 顶板 / 侧壁厚 | 3.6 / 3.2 mm |
| 竖直棱圆角 | R6 |
| 挡边 | 4mm 高 × 3mm 厚，仅后 + 左 + 右 |
| 前端斜坡 | 45 mm 渐隐 |
| 实体体积 | 61.9 cm³ |
| 网格 | 1236 三角面，水密 |

挡边只做靠打印机那一侧加左右共三面，作用不是"防止滑走"，是**顶住打印机送纸的拉力**：面单连着机内的纸卷，送纸时整张纸都在被往打印机方向拽，台面上没有这道边，一拉就顺着走纸方向滑出去、掉进架子和打印机之间的缝里。前面不设边、留敞口，是因为前面是伸手取面单的一侧；前 45mm 做渐隐斜坡，挡边从零高度升到全高，手伸进去不刮。

## 打印方向的坑

**这是整个项目最容易踩的地方，第一版定稿时的判断是错的。**

零件本质上是一个「П 形槽」，无论怎么平放，都有一大片朝下的平面：

**正放（顶板朝上）**
顶板背面是一整片朝下的平面，跨度 79.6mm。两个侧壁是唯一的锚点，中间完全没有支撑——这不是"桥接"能糊弄过去的距离（一般打印机 30~50mm 就到极限了），会塌。想加支撑，则是 80×130 一整片，拆起来是灾难。

**倒扣（顶面朝下）**
看起来合理，其实更糟：4mm 挡边会先接触热床，把整块顶板顶起来 4mm，于是顶板整片悬空，同样需要满片支撑。

**侧立（正确解法）**
把模型绕 X 轴转 90°，让 133mm 的长边竖直、挡边那一端朝下贴在热床上。这时**每一层的截面几乎完全相同**——一个 П 形环，全是竖直墙，没有悬空面。顶板不再是"一片要桥接的平板"，而是"一面竖着长上来的墙"。

零支撑、零桥接。代价是打印高度变成 133mm，接触面积只有 86×29，需要 brim（5~8mm），外壁速度降到 40mm/s 左右。

这个结论也解释了为什么这个形状天生适合立着打：它是个**等截面拉伸体**，截面几乎不随长度变化。凡是这种形状，侧立打印永远是最优解。

## 建模笔记（build123d）

几个实际踩到的点：

**`chamfer` 在挡边顶面边组上会失败**。挡边和前端的斜坡切口相交，`chamfer(top_edges, 0.35)` 以上就报错。改用 `fillet(top_edges, 0.4)` 平滑处理，效果上其实更好——挡边顶端圆角比倒角手感更舒服。

```python
top_edges = body.edges().filter_by(Plane.XY).group_by(Axis.Z)[-1]
body = fillet(top_edges, 0.4)
```

**Python 3.13 装不上 build123d**。它依赖的 OCP 还没有对应 wheel，必须用 Python 3.11 建虚拟环境。

**判断点是否在实体内时，`State()` 的返回值不能靠猜**。`BRepClass3d_SolidClassifier` 返回的是 `TopAbs_IN` / `TopAbs_OUT` 枚举，用 `str(state).endswith('IN')` 判断：

```python
state = BRepClass3d_SolidClassifier(part.wrapped, gp_Pnt(x, y, z), 1e-6).State()
inside = str(state).endswith('IN')
```

用 `== 1` 或者 `'In' in name` 都会静默判错——前者是因为枚举值不是 1，后者是因为 `TopAbs_IN` 里没有小写的 `In`。这种错误不会报异常，只会让你在错误的结论上继续走。

借这个工具逐点验证过：卡扣槽宽 3.4 / 臂厚 1.6 / 封底 1.6，以及 v3 的前（Y=-65）、后（Y=+68）、下（Z=0）三面确实全部敞开。

## 预览渲染器

机器上没有 CAD 软件，build123d 也不带可视化，模型建完没法直接看。所以写了个 40 行的软件渲染器 `codes/render.py`：读二进制 STL → 透视投影 → z-buffer 光栅化 → 简单光照 + 轮廓线 → PNG。

它只依赖 numpy 和 Pillow，和建模完全解耦，不参与 STL/STEP 的生成。

自己写的过程中翻过两次车，都记一下：

- **相机仰角要换算**：直觉上 `el` 是仰角，但旋转矩阵里要用 `90 - el`，否则得到的是俯仰颠倒的图。
- **屏幕 y 不要二次取反**：投影完相机空间 y 已经符合屏幕方向了，再乘 `-1` 会上下颠倒。

这两个错误都会产生"看起来像模型坏了"的图，当时一度以为几何有问题，白查了半天。

## 目录与构建

```
codes/riser.py       参数化建模脚本，参数区在文件头
codes/render.py      预览渲染器
output/riser.stl     可打印网格（生成物）
output/riser.step    可编辑实体（生成物）
output/preview_*.png 渲染预览（生成物）
```

两个脚本的输出路径都锚定在脚本自身位置，从任何目录运行都会写到项目根的 `output/`：

```python
OUT = Path(__file__).resolve().parent.parent / "output"
```

`output/` 里的文件都是生成物，删了跑一遍就能重建。真正的源头只有 `codes/riser.py`。
